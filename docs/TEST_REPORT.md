**Test strategy.** The automated suite replaces only the network-facing LLM call (`agent.llm_client._chat`) with a deterministic fake that returns a canned JSON response for each role. Everything above it runs for real: retries, JSON parsing, planner validation, the orchestrator, all tools, the RAG pipeline, guardrails and PDF parsing. Test PDFs are real files generated by `tests/pdf_factory.py`. The fake can also inject failures (rate limits, malformed JSON, unsupported answers, API errors) to test error handling. A separate integration test runs the **real** embedding model on real arXiv papers.

Test environment: macOS, Python 3.12, Streamlit 1.65, dependencies pinned in `requirements.txt`.

## Defects found and fixed during testing

| # | Defect | Found by | Fix |
|---|---|---|---|
| 1 | `groq==0.11.0` + `httpx 0.28` → `TypeError: unexpected keyword argument 'proxies'`; **no LLM call could succeed** on a fresh install | client smoke test | upgraded the SDK (now pinned at `groq==1.7.0`) |
| 2 | `pyarrow>=18` needs NumPy 2 but `numpy==1.26.4` is pinned → **every `st.dataframe` / chart crashed** | headless UI test | pinned `pyarrow==17.0.0` |
| 3 | Two-column PDFs: merged words and interleaved columns; section detection failed | real-paper retrieval test | layout-aware extraction (`extract_page_text`) |
| 4 | macOS python.org builds lack root certificates → arXiv/OpenAlex HTTPS failed | live API test | `certifi` SSL context |
| 5 | Guardrail false positive on the legitimate phrase "system prompt" | real-paper scan | narrowed pattern + regression test |
| 6 | Consecutive chat submissions occasionally dropped (`st.rerun` inside a form) | headless UI test | callback-based query queue |
| 7 | LLM usage counted in the wrong layer (missed when the low-level call was replaced) | unit test | moved accounting into `call_llm` |
| 8 | **50+ known CVEs** in pinned dependencies (incl. `pdfminer.six`, which parses untrusted PDFs, and Streamlit) | `pip-audit` | upgraded and re-pinned the stack; 0 known vulnerabilities |
| 9 | **XSS**: paper/LLM/API text rendered with `unsafe_allow_html` | code review + browser test | escaped HTML components, Markdown-only for untrusted text, URL allow-list |
| 10 | **Shared API key**: a key pasted in the UI was written to `os.environ`, so it was visible to every user of a deployed app | code review | session-scoped `ContextVar`, propagated to worker threads |
| 11 | Guardrails bypassed by zero-width/full-width characters | security test | Unicode normalisation before matching |
| 12 | **Live run: analysis failed** — `gpt-oss-20b` (reasoning model) exhausted its token budget before finishing JSON (`json_validate_failed`) | live browser test with real key | `reasoning_effort="low"`, `max_completion_tokens`, retry without JSON mode |
| 13 | **Fallback model retired** (`llama-3.3-70b-versatile` → 404) | live test | fallback `openai/gpt-oss-120b`; 404 models skipped automatically |
| 14 | Free-tier limit of 8k tokens/min per model made full runs take 2+ minutes | live test (rate-limit headers) | dual-model load balancing honouring `Retry-After`; ~40% smaller prompts |
| 16 | Planner sometimes skipped the prior-work check for research gaps (live TC06) | live test output review | `search_related_work` added by policy whenever gaps are generated + test |
| 17 | Two-column detection split the full-width title ("Corrective Retrieval A") | live browser screenshot | header band extracted before column split + regression test on the real paper |
| 18 | **A single LLM request stalled for ~26 minutes** (SDK default timeout plus hidden SDK retries) | evaluation run | 45 s per-request timeout, SDK retries disabled (our scheduler retries) |
| 19 | Benchmark scoring missed LLM typography (`RAG‑Token` with a non-breaking hyphen, `150 k` with a narrow no-break space) | evaluation output review | Unicode normalisation in metrics + regression test |
| 20 | Honest but incomplete answers when the first search missed the key passage (benchmark Q06/Q10/Q12) | evaluation benchmark | answerability-driven second search: if the draft says the evidence is insufficient, rewrite the query around what is missing, retrieve again and keep the better answer + 2 tests |
| 21 | Sign-in fields invisible (white inputs on a white card) | browser screenshot | iOS grey text-field styling on cards |
| 15 | Streamlit file watcher crawled `transformers` modules (errors, slow start); server exposed on all network interfaces | browser test logs | `fileWatcherType = "none"`, `address = "localhost"` |
